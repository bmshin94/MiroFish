## 1. 한 줄 정의

> **"수백~수천 개의 AI 에이전트가 사는 가짜 소셜미디어(트위터/레딧)를 자동으로 만들어서,
> 실제 사건이 터지면 여론이 어떻게 흘러갈지 미리 돌려보는 시뮬레이터"**

### 이름의 의미 — 군집 지능 (Swarm Intelligence)

물고기 한 마리는 단순하지만, 수천 마리가 모이면 상어를 피하고 먹이를 찾는 집단 지능이 나타난다.
MiroFish는 같은 원리를 적용한다.

- AI 하나에게 "미래 어떻게 될까?" 물으면 → **편향된 일반론**
- 성격이 제각각인 AI 수백 개를 서로 상호작용하게 두면 → **실제 사회에서 벌어질 법한 창발(emergence)**

### 비유: "심즈 + 트위터 + 타임머신"

- 캐릭터가 집이 아니라 **소셜미디어에 산다**
- 캐릭터가 **업로드한 PDF 문서에서 자동 생성된다**
- 캐릭터 머리에 **진짜 LLM이 들어있다** (그래서 비용이 든다)
- 끝나면 **AI가 "그래서 어떻게 됐는지" 보고서를 쓴다**

## 3. 5단계 파이프라인 (코드 기준)

### STEP 1. 그래프 구축 — `ontology_generator.py` → `graph_builder.py`

| 단계 | 하는 일 |
|---|---|
| ① 업로드 | PDF / MD / TXT (최대 50MB). PyMuPDF로 추출, 인코딩 자동 감지 |
| ② 청킹 | 500자 단위, 50자 겹침 |
| ③ **온톨로지 자동 설계** | LLM이 "이 사건의 주체(Entity)와 관계(Relation) 종류"를 JSON으로 설계 |
| ④ **지식그래프 적재** | Zep Cloud에 Batch API로 350개씩 전송 + 완료 폴링 |

핵심: 온톨로지 프롬프트가 *"실체는 현실에 존재하며 소셜미디어에서 발언·상호작용할 수 있는 주체여야 한다"* 고
강제한다. 즉 **계정을 가질 수 있는 존재**만 추출한다.

### STEP 2. 환경 세팅 — `zep_entity_reader.py` → `oasis_profile_generator.py` → `simulation_config_generator.py`

| 단계 | 하는 일 |
|---|---|
| ① 엔티티 추출 | Zep 그래프에서 모든 노드 읽기 |
| ② **2차 정보 보강** | 엔티티별로 Zep 재검색 → 관련 fact/edge 수집 |
| ③ **페르소나 생성** | 나이·성별·MBTI·직업·말투·정치성향·관심사·행동패턴. **개인/집단 구분 프롬프트** |
| ④ 포맷 변환 | Twitter용 CSV, Reddit용 JSON |
| ⑤ **파라미터 자동 생성** | 시간 → 사건 → 에이전트 활동도 → 플랫폼, **4단계 분할 생성** |

주목할 디테일: `CHINA_TIMEZONE_CONFIG` 가 하드코딩되어 있다.
새벽 0~5시 활동계수 **0.05**, 저녁 19~22시 **1.5** → 실제 생활 리듬을 반영한다.

### STEP 3. 시뮬레이션 — `simulation_runner.py` → `scripts/run_parallel_simulation.py`

- 백엔드가 **별도 Python 프로세스를 subprocess로 기동** (Flask가 죽어도 독립 생존)
- **OASIS 엔진**(camel-oasis 0.2.5 / camel-ai 0.2.78) 위에서 동작
- **Twitter와 Reddit 동시 병렬 시뮬레이션**

| 플랫폼 | 가능한 행동 |
|---|---|
| Twitter | CREATE_POST, LIKE_POST, REPOST, FOLLOW, QUOTE_POST, DO_NOTHING |
| Reddit | LIKE/DISLIKE_POST, CREATE_POST, CREATE_COMMENT, LIKE/DISLIKE_COMMENT, SEARCH_POSTS, SEARCH_USER, TREND, REFRESH, FOLLOW, MUTE, DO_NOTHING |

- 모든 행동 → `action_logger.py` JSONL 실시간 로그 → 프런트 라이브 모니터링
- **IPC(소켓)** 로 일시정지 / 중단 / 인터뷰 / 환경종료 명령 전송
- **Dynamic Temporal Memory Update**: 시뮬 중 발생한 사건이 `zep_graph_memory_updater.py`를 통해
  다시 Zep 그래프에 기록 → 에이전트 집단 기억이 시간에 따라 진화

### STEP 4. 보고서 생성 — `report_agent.py` + `zep_tools.py`

단순 요약이 아니라 **ReAct 패턴 에이전트**:

1. 목차 먼저 설계 → 섹션별 분할 생성
2. 섹션마다 **생각 → 도구호출 → 관찰 → 반성** 루프
   (도구호출 최대 5회 / 반성 2라운드, `REPORT_AGENT_*` 설정으로 조절)
3. 전용 도구 세트:

| 도구 | 기능 |
|---|---|
| `search_graph` | 그래프 시맨틱 검색 |
| `insight_forge` | 질문을 하위질문으로 분해해 다각도 심층 조사 |
| `panorama_search` | 전경 파노라마 조사 |
| `quick_search` | 빠른 조회 |
| **`interview_agents`** | **시뮬레이션 속 에이전트를 직접 인터뷰** ★MiroFish의 백미 |
| `get_graph_statistics` | 그래프 통계 |
| `get_entity_summary` / `get_node_edges` | 엔티티 상세 / 관계 조회 |

보고서 쓰는 AI가 "이 결론이 맞나?" 싶으면 **가상 시민에게 직접 질문**해 근거로 삼는다.
전 과정이 `agent_log.jsonl` 로 기록되고 **SSE 스트리밍**으로 사용자가 사고과정을 실시간 관전한다.

### STEP 5. 심층 상호작용

- 시뮬 종료 후에도 **환경을 닫지 않고 대기 모드** 유지
- 아무 에이전트에게나 말 걸기 (단일 / 배치 / 전체 인터뷰)
- ReportAgent와 채팅으로 추가 질문
- `close-env` 호출 전까지 세계가 살아있음

### 전체 흐름도

```
  📄 문서            💬 자연어 요구사항
      └──────┬──────────┘
             ▼
  ① 온톨로지 자동 설계 (LLM)        "출연진 분류표"
             ▼
  ② 지식그래프 구축 (Zep Cloud)     ↕ 시뮬 중에도 계속 갱신
             ▼
  ③ 페르소나 대량 생성 (LLM × N)    "캐스팅 + 스케줄표"
             ▼
  ④ 병렬 소셜 시뮬레이션 (OASIS)
       🐦 Twitter판   👽 Reddit판
       Round 1→2→...→N (매 라운드 전원 LLM으로 행동 결정)
             ▼
  ⑤ ReportAgent (ReAct)            생각→도구→관찰→반성
       ↳ 가상시민 인터뷰 가능
             ▼
  📊 예측 보고서  +  🗣️ 살아있는 세계와 대화
```

## 6. 설치 및 사용법

### 방법 A — Docker (추천, 5분)

```bash
git clone https://github.com/bmshin94/MiroFish.git
cd MiroFish
cp .env.example .env     # Windows: copy .env.example .env
# .env 편집해서 키 2개 입력
docker compose up -d
# → http://localhost:3000
```

중지: `docker compose down`

### 방법 B — 소스 코드 (개발·수정용)

사전 준비물

| 도구 | 버전 | 확인 |
|---|---|---|
| Node.js | 18 이상 | `node -v` |
| Python | **3.11 또는 3.12** (3.13 불가) | `python --version` |
| uv | 최신 | `uv --version` |

```bash
# uv 설치
curl -LsSf https://astral.sh/uv/install.sh | sh                      # macOS/Linux
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"           # Windows

git clone https://github.com/bmshin94/MiroFish.git
cd MiroFish
cp .env.example .env
npm run setup:all        # 루트 + 프런트 + 백엔드 의존성
npm run dev              # 프런트 + 백엔드 동시 실행
```

개별 실행: `npm run backend` / `npm run frontend` / `npm run build`

### 화면 사용 흐름

```
① Home → 새 프로젝트
② Step1 Graph Build   : 파일 업로드 + 요구사항 입력 → 온톨로지 생성 → 그래프 구축
③ Step2 Env Setup     : 프로필 생성 (실시간) → 시뮬 설정 자동 생성
④ Step3 Simulation    : 시작 → 라운드별 행동 실시간 피드 + D3 관계망
⑤ Step4 Report        : AI 사고과정 스트리밍 관전 → Markdown 다운로드
⑥ Step5 Interaction   : 에이전트와 대화 / ReportAgent 추가 질문 → 환경 종료
```

### 자주 터지는 문제

| 증상 | 해결 |
|---|---|
| `LLM_API_KEY 未配置` | `.env`가 **루트**에 있는지 확인 (backend/ 아님) |
| `ZEP_API_URL 不受支持` | **그 줄을 삭제.** Zep Cloud 전용임 |
| Python 버전 오류 | 3.11 또는 3.12로 변경 |
| 포트 충돌 | `FLASK_PORT=5002` |
| LLM_BOOST 관련 오류 | `.env`에서 LLM_BOOST_* **3줄을 아예 삭제** |
| 한글 깨짐 (Windows) | Windows Terminal 사용 (코드엔 이미 UTF-8 처리 있음) |

## 7. 핵심 질문 7개 정리

### Q1. 플러그인? 스킬? MCP?

**셋 다 아니다. 독립 실행형 풀스택 웹 애플리케이션이다.**

| 용어 | MiroFish |
|---|---|
| 플러그인 | ❌ 끼워 넣을 호스트가 없음 |
| 스킬 | ❌ 지침이 아니라 실행 코드 |
| MCP 서버 | ❌ MCP 의존성·코드 전무 (코드 확인) |
| **독립 웹앱** | ✅ **이것** (Vue SPA + Flask REST API) |

단, **MCP 서버로 만들 수 있다.** REST API 60개가 이미 있으므로 얇은 래퍼만 씌우면
Claude Code / Cursor 안에서 바로 호출 가능해진다. (아래 수익화 아이디어 5번)

참고: MCP는 아니지만 `report_agent.py`는 **자체 Function Calling**으로 8개 도구를 LLM에 노출한다.
즉 "MCP와 같은 아이디어를 MCP 표준 없이 자체 구현"한 상태 → 표준으로 꺼내기 좋은 구조.

### Q2. API 토큰이 필요한가?

**필수 2개 + 선택 1개.**

| 키 | 필수 | 용도 |
|---|:---:|---|
| `LLM_API_KEY` | ✅ | 온톨로지·페르소나·에이전트 행동·보고서 전부 |
| `ZEP_API_KEY` | ✅ | 지식그래프 저장·검색·시간기억 |
| `LLM_BOOST_*` | ⬜ | 저가/고속 모델 분리 (없으면 메인 모델 사용) |

`backend/app/config.py`의 `Config.validate()`가 둘 중 하나라도 없으면 `run.py`가 `sys.exit(1)` → **우회 불가.**

#### 비용 구조 (핵심 쟁점)

```
총 LLM 호출 ≈ 온톨로지 + 페르소나(×N) + 설정(4~10)
            + 🔥 에이전트 행동 (× N × 라운드 R)   ← 대부분이 여기
            + 메모리 업데이트(×R) + 보고서(섹션 × 7)
```

| 규모 | 에이전트 | 라운드 | 총 호출 | 대략 비용 | 시간 |
|---|---:|---:|---:|---|---|
| 테스트 | 20 | 10 | ~250 | $0.3 ~ $1 | 10~20분 |
| 소규모 | 50 | 30 | ~1,700 | $2 ~ $6 | 1~2시간 |
| 중규모 | 100 | 40 | ~4,300 | $8 ~ $25 | 3~5시간 |
| 대규모 | 300 | 100 | ~30,500 | $60 ~ $250 | 하루+ |

> README 공식 경고: **"소비량이 크니 40라운드 미만으로 먼저 시도하라"**

비용 절감 5가지
1. DeepSeek-chat 사용 (gpt-4o-mini의 1/3~1/5)
2. `LLM_BOOST_*` 분리 — 에이전트 행동은 싼 모델, 보고서는 좋은 모델
3. 에이전트 수 줄이기 (비용은 N에 선형, 다양성은 N에 로그 → **50명이 스위트스팟**)
4. `OASIS_DEFAULT_MAX_ROUNDS` 제한
5. `REPORT_AGENT_MAX_TOOL_CALLS=3`, `REPORT_AGENT_MAX_REFLECTION_ROUNDS=1`

#### 보안 주의
- `.env`는 `.gitignore`에 포함됨 ✅ / Docker 이미지에 굽지 말 것
- `CORS(origins="*")` → **전체 허용.** 외부 노출 시 반드시 수정
- **인증·인가 로직 전혀 없음.** 로컬 전용 설계. 공개 배포 시 직접 구현 필요 ⚠️

### Q3. AI 에이전트 구축에 도움이 되는가? → 매우 크다

여기서 배울 수 있는 실전 패턴 10가지

| # | 패턴 | 교훈 |
|---|---|---|
| ① | LLM으로 스키마 설계 (`ontology_generator.py`) | **LLM에 자유를 주되 출력은 코드로 강제 정규화** |
| ② | 분할 생성 (`simulation_config_generator.py`) | **한 번에 다 만들라면 반드시 잘린다. 쪼개라** |
| ③ | 깨진 JSON 자동 복구 (`_fix_truncated_json`, `_try_fix_json`) | **파싱 실패는 일상. 3단계 폴백 준비** |
| ④ | ReAct + Reflection (`report_agent.py`) | **무한루프 가드레일을 처음부터 설정값으로** |
| ⑤ | Temporal Knowledge Graph (`is_expired`, `is_invalid`) | **에이전트 기억엔 벡터DB만으론 부족. 시간성 필요** |
| ⑥ | 장시간 작업 (Task + 폴링 + SSE) | **AI 작업은 분 단위. 동기 설계는 100% 타임아웃** |
| ⑦ | 프로세스 분리 + IPC + atexit/signal | **무거운 에이전트 루프를 웹서버 스레드에 올리지 말 것** |
| ⑧ | 병렬 생성 + 실시간 저장 (`save_profiles_realtime`) | **"다 끝나고 저장"이 아니라 "되는 대로 저장"** |
| ⑨ | 지능적 재시도 (`utils/retry.py`, `is_retryable_zep_error`) | **재시도 가치가 있는 에러만 재시도** |
| ⑩ | LLM 공급자 추상화 (`openai_chat_compat.py`) | **OpenAI 호환이라도 차이가 있다. 어댑터를 두라** |

### Q4. React나 PHP로 만들 수 있는가?

**React는 YES (난이도 ⭐⭐). PHP는 "프런트/게이트웨이 YES, 엔진 NO".**

#### React — 완전히 가능

백엔드가 순수 REST API라 프런트는 완전 교체 가능. **백엔드 수정 0줄.**

| Vue 3 | React 대응 |
|---|---|
| `vue-router` | `react-router-dom` |
| `vue-i18n` | `react-i18next` |
| `ref` / `reactive` | `useState` / `useReducer` |
| `computed` / `watch` | `useMemo` / `useEffect` |
| `<script setup>` SFC | 함수형 컴포넌트 |
| `d3` (GraphPanel) | `d3` 그대로 또는 `react-force-graph` |
| axios 인스턴스 | **그대로 복붙 가능** |

추천 스택: `Next.js 15 (App Router) + TypeScript + TanStack Query + shadcn/ui + react-force-graph-2d + EventSource(SSE)`

작업량: **1인 기준 약 12~14일**

| 화면 | 공수 |
|---|---|
| Home / 프로젝트 목록 | 0.5일 |
| Step1 업로드 + 온톨로지 | 1.5일 |
| Step2 프로필 (실시간) | 1.5일 |
| Step3 시뮬 모니터링 | 2일 |
| **GraphPanel (D3)** | 2~3일 |
| Step4 보고서 + SSE | 2일 |
| Step5 인터랙션 채팅 | 1.5일 |
| i18n / 공통 | 1일 |

꿀팁: `frontend/src/api/*.js` 4개 파일은 거의 그대로 재사용 가능 → 공수 20% 절감.

#### PHP — 반만 가능

되는 것
- **(a) 프런트엔드 전체** — Laravel + Blade/Livewire 또는 Inertia.js
- **(b) API 게이트웨이 / 멀티테넌시 레이어** ⭐실전 추천
- **(c) 결과 뷰어 / 리포트 포털**

```
사용자 ──> Laravel (인증·결제·쿼터·로그·관리자)
              └─ 내부 HTTP ──> Flask MiroFish (엔진, 그대로)
```

MiroFish에 **없는 것**(인증·과금·멀티테넌시·관리자)을 PHP로 덮는 구조. **가장 현실적이고 가치 있는 조합.**

안 되는 것 — 시뮬레이션 엔진 본체

| 장벽 | 설명 |
|---|---|
| OASIS 엔진 | `camel-oasis`는 Python 전용, PHP 포팅 없음 → 처음부터 재작성 |
| CAMEL-AI | Python 전용 멀티에이전트 프레임워크 |
| Zep SDK | 공식 PHP SDK 없음 (REST 수작업 필요) |
| asyncio 동시성 | 수백 에이전트 비동기 루프. PHP는 Swoole/ReactPHP 필요 + 생태계 빈약 |
| PyMuPDF | PHP 대안 품질 차이 |
| 장기 실행 | PHP-FPM은 요청-응답 모델 |

냉정한 추정: 엔진 전체 PHP 재작성 = **수개월~1년 + 숙련 개발자 다수**, 결과물은 더 느리고 불안정할 가능성.
→ **하지 말 것.**

#### 최종 권장 아키텍처

```
┌──────────────────────────────────────┐
│ 프런트엔드  Next.js(React) + TS      │ ← 바꾸고 싶으면 여기
└──────────────┬───────────────────────┘
               │ REST / SSE
┌──────────────▼───────────────────────┐
│ 게이트웨이(선택) Laravel or NestJS   │ ← 인증·결제·쿼터
└──────────────┬───────────────────────┘
               │ 내부 HTTP
┌──────────────▼───────────────────────┐
│ 🔒 엔진 (손대지 말 것)                │
│    Flask + OASIS + Zep (Python)      │
└──────────────────────────────────────┘
```

**원칙: 엔진은 Python으로 두고, 껍데기만 원하는 언어로.**

### 🥇 1순위 — PR/위기관리 "디지털 리허설" 컨설팅

왜 최고 ROI인가:
> 기업 위기관리 컨설팅은 이미 비싸고 근거가 빈약하다.
> "제 경험상 이렇게 하시면 됩니다" → 수천만원.
> 여기에 **"AI 500명 시뮬레이션 결과입니다"** 를 얹으면 같은 돈에 설득력이 10배.

타깃 고객

| 고객군 | 니즈 | 단가 |
|---|---|---|
| PR 에이전시 | 제안서 차별화 무기 | 건당 300~800만 |
| 대기업 홍보실 | 위기 대응 시나리오 | 건당 1,000~3,000만 |
| 정치 캠프 | 메시지 테스트 | 건당 500~2,000만 |
| 공공기관 | 정책 수용성 평가 | 용역 2,000만~1억 |
| 로펌 위기관리팀 | 평판 리스크 평가 | 건당 500~1,500만 |

패키지 설계

```

   에이전트 50명 × 30라운드, 단일 시나리오, 보고서 PDF 20p, 1시간 브리핑

📦 STANDARD 900만원 / 10영업일  ⭐주력
   150명 × 50라운드, 시나리오 3종 비교(A안/B안/무대응),
   플랫폼별 분리 분석, 대응 메시지 초안, 2시간 워크숍

📦 PREMIUM  2,500만원 / 1개월
   300명 × 100라운드, 시나리오 5종 + 민감도 분석,
   🔥 핵심 여론층 인터뷰 트랜스크립트, 주간 리포트 4회,
   임원 발표, 3개월 모니터링 자문
```

**결정적 차별점 — 인터뷰 트랜스크립트**

MiroFish만의 무기. 보고서에 이런 것이 들어간다:

> **부록 C. 핵심 반발층 심층 인터뷰 (발췌)**
>
> *Q. 사과문을 보고 어떤 생각이 드셨나요?*
> *A-47 (29세 여성, 기존 충성고객): "제일 화났던 건 '우려를 끼쳐드려'라는 표현이었어요.
> 우려를 끼친 게 아니라 피해를 입힌 거잖아요. 그 한 문장에서 '아 얘네 아직 모르는구나' 싶었어요."*
>
> → **권고: 사과문 1문단의 '우려' → '피해'로 수정**

경쟁사는 이걸 못 준다. 설문조사로는 이 깊이가 안 나오고, FGI는 건당 수천만원에 2주 걸린다.

영업 전략
1. **무료 샘플 리포트 3건 제작** (이미 공개된 과거 이슈로)
2. PR 에이전시 10곳 콜드메일
3. 1곳만 뚫리면 레퍼런스 확보
4. 링크드인 케이스 스터디 연재
